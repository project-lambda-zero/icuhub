10. `mend_sca`
11. `invicti_enterprise`
12. `invicti_standard`
13. `kubernetes`
14. `openshift`
15. `prisma_cloud`, with `cspm` and `compute` as two DoD units
16. `archer`, covering on-premises and SaaS as one kind

ADR-0020 also retains three wave-1 units: `f5_bigip`, `google_threat_intelligence`, and the `smtp` notifier. The resulting scope is 17 MVP DoD units plus 3 retained wave-1 units.

The MVP runtime comprises the connector kit; Postgres storage with row-level security; credential broker; typed policy; action state machine with approvals; hash-chained audit; job queue; sync engine; webhook ingress; report-file import; transactional outbox with Kafka relay; REST `/v1`; MCP `/mcp`; ticket routing with cross-scanner correlation; and SMTP notifier. ADR-0021 fixes the additional service-stack dependencies and the offline test dependency boundary.

## 2 Persona review

### AppSec program lead

- Connector-specific fingerprints can turn one logical problem into a ticket storm. **Design change:** preserve source observations, correlate them into tenant-scoped cases, and key ticket creation by `(tenant_id, route_id, correlation_case_id)`.
- A timeout after a Jira create can duplicate an issue, while search index lag can hide the original. **Design change:** persist action identity before send, enter `outcome_unknown`, and reconcile by route key and remote identity before any retry.
- Jira completion is not scanner resolution, and partial reads can resemble genuine zero findings. **Design change:** separate detection, remediation, and exception ownership; permit absence closure only after a complete authoritative snapshot with a removal circuit breaker.
- Scanner triage and evidence lose value when flattened. **Design change:** retain vendor revisions, suppression state, dependency and location context, bounded evidence, and explicit `not_evaluated` coverage for denied or truncated scopes.

### GRC / risk analyst

- Archer applications, findings, risks, and exceptions have installation-specific fields and different cardinality. **Design change:** use runtime metadata discovery and tenant-configured record, field, relationship, and natural-key mappings rather than a generic risk stream or hard-coded identifiers.
- One risk per alert duplicates enterprise risk, while arbitrary field mirroring creates conflicts. **Design change:** link cases to policy-selected applications and risks, limit writes to approved mappings, and keep Archer authoritative for risk judgment.
- Exception approval, source suppression, and expiry can diverge. **Design change:** require a separate approved source-action plan after Archer approval, preserve exact scope and expiry, and reconcile rejection and expiry without implicit suppression.
- Audit requires more than a hub execution log. **Design change:** maintain digest-addressed evidence manifests linking observations, mapper versions, Jira and Archer links, actors, approvals, plan hashes, outcomes, and remote revisions with tenant-controlled visibility.

### Platform / SRE on OpenShift

- A late runtime chart would leave OpenShift acceptance until after connector breadth. **Design change:** pull a minimal restricted-SCC runtime profile forward, including arbitrary UID, read-only root filesystem, Route TLS, probes, resource limits, migration, backup, and restore instructions.
- Reusing hub runtime credentials for target clusters creates excessive privilege. **Design change:** separate runtime and target-cluster identities, grant only declared `get/list/watch` reads, and enable each write through distinct credentials and policy.
- Watch expiry, managed audit blind spots, and partial RBAC can look like empty inventory. **Design change:** relist on `410`, checkpoint after commit, report unavailable audit as `not_evaluated`, and prohibit closure from incomplete partitions.
- Mutable image tags and stale full-object writes break lineage and safety. **Design change:** use image digests as stable identity, bind writes to `resourceVersion` and redacted diffs, and reconcile uncertain BuildConfig instantiation rather than repeating it.

### Cloud security engineer

- Prisma alert-time discovery is not a modification feed. **Design change:** reconcile alert detail and complete exports or snapshots so status-only changes update the existing observation.
- Compute acknowledgment filters and mutable offset pages can omit active history. **Design change:** partition complete snapshots by Console, scope, collection, asset type, and acknowledgment state; any failed page makes the affected snapshot incomplete and closes nothing.
- CSPM and Compute have different hosts, credentials, token lifetimes, and permissions. **Design change:** keep independent profiles, connection-local token state, single-flight refresh, and per-capability probes instead of inferring coverage from a successful login.
- Suppression and remediation can outlive their GRC justification or repeat after timeout. **Design change:** require preview, approval, current-state checks, read-back, `outcome_unknown` reconciliation, and explicit alignment between Prisma windows and Archer exception expiry.

### Developer / DevSecOps on GitHub and GitLab

- The native publication paths differ: GitHub accepts SARIF directly, while GitLab consumes a SARIF CI report artifact. **Design change:** reconcile GitHub analysis processing and GitLab job plus native vulnerability ingestion; never treat upload or artifact availability as final success.
- Repository paths and mutable branch heads are insufficient action identity. **Design change:** retain stable repository or project IDs and exact commit or head SHA, use action-key reconciliation for comments and changes, and reject stale head-bound plans.
- Webhooks are incomplete hints because of loss, edition limits, and vendor-specific delivery rules. **Design change:** verify the edition-specific scheme, dedupe deliveries, perform authoritative reads, and retain scheduled polling.
- Not every finding belongs in SARIF, and snippets or CI content can leak secrets. **Design change:** bound evidence, exclude secret values, and report every skipped non-code or unmappable finding with a reason instead of inventing a file location.

### Connector developer

- Happy-path goldens cannot establish complete behavior. **Design change:** require malformed, unknown-field, partial-scope, versioned, security, crash, and negative fixtures with prove gates for every advertised mapping.
- Custom async jobs, token refresh, pagination, and uncertain-outcome loops would diverge across vendors. **Design change:** put shared transport, durable async handles, typed cursors, rate limits, reconciliation, and recorded transport in the kit and host runtime.
- Shared cloud and self-managed fixtures can conceal edition and tier differences. **Design change:** maintain edition-specific feature probes, fixtures, cassettes, and live acceptance matrices, with optional failures isolated from unrelated capabilities.
- A registered class is not a completeness signal. **Design change:** publish per-kind, per-edition capability coverage and block `core` or MVP-complete labels without conformance evidence and recorded live acceptance.

### Security reviewer / attacker

- Connection and evidence URLs can become SSRF paths, and active scans can reach unapproved networks. **Design change:** enforce registered origins, resolved-address and port policy, redirect revalidation, DNS-rebinding defenses, bounded downloads, and target checks at both plan and apply.
- Secrets and active evidence can leak through logs, plans, cassettes, raw payloads, and rendered HTML. **Design change:** use `SecretRef`, write-only configuration, envelope encryption, redaction, bounded encrypted evidence, inert rendering, and canary scans across output surfaces.
- Worker roles, caches, blobs, and correlation lookups can bypass tenant boundaries. **Design change:** derive tenant only from authenticated identity, use non-bypass RLS roles with `SET LOCAL`, tenant-scope every key, and test background as well as request paths.
- Forged webhooks, stale approvals, blind retries, and malicious reports can cause side effects. **Design change:** verify before parsing, use exact per-kind verifiers and delivery dedupe, bind approval to the resolved plan hash, reconcile unknown outcomes, and apply safe XML/JSON/ZIP limits.

### Product owner

- A single scanner-to-Jira demo does not prove the central deduplication claim. **Design change:** make the first vertical slice Fortify SSC plus Nessus file import, shared asset mapping, one explainable correlation case, and Jira Cloud with crash and reconciliation tests.
- GRC, developer, and deployment value need distinct proofs. **Design change:** demonstrate Prisma to Archer exception handling, GitHub and GitLab native publication, and restricted OpenShift runtime plus target reads rather than treating OCSF ingestion alone as product completion.
- Broad package counts can hide missing editions and profiles. **Design change:** define completion per advertised capability and attach automated evidence plus dated live acceptance, with explicit exclusions and no aggregate completion claim that conceals gaps.
- Infrastructure breadth can delay the value slice. **Design change:** deliver vertical flows first while retaining the ADR-0020 release boundary for Kafka, MCP, and SMTP; durable Postgres outbox and audit remain part of the initial slice.

## 3 Identity and state ownership

The MVP uses four distinct record types rather than overloading a connector-specific finding fingerprint:

| Record | Planned identity and ownership rule |
|---|---|
| Source observation | One vendor record with `connection_id`, source record ID and revision, parser and mapper versions, raw evidence reference, and its per-connector fingerprint. Correlation never deletes or overwrites vendor-specific observation fields (FR-COR-01). |
| Correlation case | One ICUHUB-owned logical remediation problem per tenant, with a versioned vendor-neutral `correlation_key`, canonical asset references, confidence, and audited split/merge history. Strong keys use vulnerability identity, canonical asset, and component; observations without a strong key remain separate (FR-COR-02, FR-COR-03). |
| External link | A durable tenant-scoped link from a case to a Jira issue, Archer record, or other route object, storing remote ID and revision, route ID, last inbound and outbound revisions, and reconciliation state. Ticket idempotency uses `(tenant_id, route_id, correlation_case_id)` (FR-COR-04). |
| Evidence item | A digest-addressed manifest member for source payloads, reports, attachments, plans, approvals, outcomes, and mapping versions. It proves what ICUHUB observed and did, not the underlying vendor security claim; Archer evidence writes carry the digest (FR-GRC-03). |

| State | Authoritative owner | MVP rule |
|---|---|---|
| Detection and source resolution | Scanner or posture vendor | Jira or Archer must not mark a source finding fixed. Only explicit vendor state or a complete authoritative source snapshot can do so (FR-COR-05). |
| Remediation workflow | Jira for the linked issue | Jira status updates case remediation state without silently changing source detection state (FR-COR-05). |
| Risk acceptance and exception approval | Archer when selected as GRC authority | An approved, unexpired exception can drive source suppression only through a separate approved plan and policy decision (FR-COR-05, FR-GRC-04). |
| Correlation and route links | ICUHUB | Split, merge, relink, and route changes are audited hub operations (FR-COR-03). |
| Asset and application mapping | Operator-approved mapping with source references | Names alone are insufficient; stable repository, cloud resource, host, application, and digest identities are preferred (FR-COR-02). |

For Archer, logical finding, risk, exception, and application types map to tenant-configured application and field identifiers discovered through GRC metadata, never hard-coded IDs (FR-GRC-01). Incremental reads use a configured last-updated field and full snapshots; permission-limited searches never imply absence (FR-GRC-02). Finding and exception creates reconcile through the stored ICUHUB correlation key before retry, and relationship links use configured cross-reference fields (FR-GRC-03).

## 4 Definition of done

Each kind below is MVP-complete only when every capability listed for its selected editions is in the manifest and passes the global gate. This section states the planned gate. It does not claim that any gate item exists in code.

### 4.0 Global gate

Applies to every vendor kind in sections 4.1 to 4.20.

- **Discovery.** `check` and `discover` prove identity, version, edition or tier, declared scopes, selected targets, and optional features. A denied scope is `not_evaluated`, never an empty successful stream.
- **Sync.** Full, incremental, event, and replay modes where listed. Typed checkpoints commit with observations and outbox rows in one transaction. Overlap and tie IDs, async jobs, token expiry, quotas, and incomplete snapshots are tested.
- **Normalization.** OCSF 1.9.0 validation, source record identity, per-connector fingerprint, canonical AssetRef, vendor-neutral correlation inputs, raw and unmapped preservation, and parser and mapper versions are golden-tested.
- **Reads.** Every listed read goes through the same policy and audit pipeline as REST operations. Long reads use durable async handles rather than requests held open.
- **Actions.** Every listed action has a no-side-effect plan, typed diff, preconditions, approval behavior, idempotency, `accepted_async` and `outcome_unknown` handling where relevant, and read-back. Destructive actions are disabled by default. An action that cannot be verified ends as `unverified`, never silently `succeeded`.
- **Webhooks.** Verification, dedupe, rotation, replay, and poll reconciliation are tested where supported. No webhook is fabricated for polling-only vendors.
- **Conformance.** Positive and negative fixtures, the prove gate, HTTP replay fixtures (no `vcrpy`; see section 6), malicious-input tests, crash recovery, tenant isolation, and opt-in live acceptance pass for each advertised edition and auth mode.
- **Operations.** Documentation covers least privilege, CA and proxy, quotas, backfill, retention, target selection, known limitations, and recovery. No unresolved vendor fact remains on an advertised path.

## 5 Phases

| Phase | Name | Exit criterion |
|---|---|---|
| M1 | Write | The planning set agrees on MVP scope, flow ownership, connector contracts, dependencies, and release gates. |
| M2 | Kit | The `icuhub.kit` public API and its offline behavioral tests support every connector family without connector-owned HTTP or environment access. |
| M3 | Core runtime | The durable multi-tenant runtime executes syncs and governed actions, exposes REST and MCP, and preserves evidence across restarts. |
| M4 | Connectors | Every selected kind, edition, and profile passes offline fixtures and the shared conformance gate. |
| M5 | Cross-vendor flows | F1 through F7 pass their offline demo oracles, including failure recovery, echo suppression, and evidence traversal. |
| M6 | Acceptance and release | Offline smoke and operator-run live acceptance reports pass, and the patch release `0.0.2` is ready. |
| M7 | Post-MVP backlog | Should and could gaps and explicitly deferrable capabilities are prioritized without weakening the MVP boundary. |

### M5 Cross-vendor flows

**Tasks**

- Implement **F1, Scanner findings -> OCSF -> correlation -> Jira -> status sync** across Fortify, Mend, Invicti, Nessus, and Jira. Preserve encrypted evidence and unmapped data, atomically commit observations, outbox, and checkpoints, correlate without overwriting source fields, route by `(tenant_id, route_id, correlation_case_id)`, reconcile uncertain creates, and keep source detection separate from Jira remediation state.
- Implement **F2, Jira or Archer triage -> source action without loops** across Jira, Archer, Fortify, Mend, Invicti, and Prisma. Apply authority-aware directives only through approved current-revision plans, persist outbound revisions, suppress hub-authored echoes, and reopen or reconcile expired exceptions explicitly.
- Implement **F3, Prisma alert -> Archer finding/risk -> exception -> governed suppression** for Prisma CSPM and Compute with optional Jira and OpenShift context. Use approved application and risk mappings, bounded evidence, exact exception scope and expiry, rejection without suppression, separate approval for source actions, and scheduled expiry reconciliation.
- Implement **F4, GitHub PR -> normalized code findings -> SARIF/code scanning -> native check**. Verify and dedupe the PR event, read authoritative head and diff data, emit SARIF 2.1.0 with skipped-item reasons, reconcile asynchronous analysis, update checks only from the reconciled result, and invalidate head-bound plans after a head change.
- Implement **F5, GitLab MR -> SARIF CI artifact -> native vulnerability ingestion -> MR feedback**. Use Standard Webhooks, reviewed CI report artifacts rather than direct SARIF upload, job and native vulnerability reconciliation, bounded result sizes, idempotent discussions, and scheduled polling.
- Implement **F6, OpenShift posture -> case -> Jira/Archer -> approved remediation evidence**. Reconcile LIST/WATCH and snapshots, map images by digest, route cases, plan only declared redacted resourceVersion-bound actions, reconcile timed-out builds, and close only from authoritative cluster state.
- Implement **F7, Audit and evidence export across every flow** through REST export or a signed evidence bundle, linking caller, tenant, correlation, connection, policy, plan hash, approval, vendor references, raw digests, outcomes, and the audit hash chain without requiring database access.

**Acceptance**

- F1 repeated scans, overlapping pages, retries, and Jira index lag produce one case and one Jira link for a strong match, preserve distinct near misses, and never treat Jira-done as scanner-fixed.
- F2 produces at most one outbound write for a hub-originated change and does not ping-pong among Jira, Archer, and a scanner; expired suppression is never silently reused.
- F3 permits traversal from Archer to case, source observation, evidence digest, approval, and Prisma read-back; rejection performs no suppression and expiry leaves no unexplained permanent suppression.

- F5 enforces artifact limits, distinguishes job success from native ingestion success, reports dropped results, and creates no duplicate MR discussion after repeated delivery.
- F6 blocks stale SCC plans, reconciles ambiguous build outcomes, preserves before and after evidence, and exposes no private key in plans or evidence views.

## 6 Test strategy

The contract makes offline behavioral evidence the default and live vendor access an explicit operator gate:

| Layer | Planned evidence |
|---|---|
| Vendor fixtures | Synthetic or permissively sourced vendor-shaped JSON and XML under `tests/fixtures/<kind>/`, with provenance in `SOURCES.md`. Tests cover mapping, pagination termination, cursor monotonicity, tamper rejection, no-write plans, typed errors, malformed and partial inputs, and edition differences. |
| Recorded transport | `httpx2.MockTransport`, kit `RecordedTransport`, and `RouteTransport` assert method, path, query, headers without secret material, pagination, throttling, and failure handling. Unmatched requests fail and cassettes assert full consumption. No live socket is needed. |
| Golden OCSF | Pure mapper output is compared with reviewed JSON goldens using `model_dump(mode="json", exclude_none=True)`. `ICUHUB_UPDATE_GOLDEN=1` is the explicit regeneration path; correlation goldens include near misses and proof that reverting a mapper removes the expected output. |
| Conformance | `conformance_problems` checks committed manifest currency, non-empty flows, stream mappers, action apply functions, `SecretRef` secret fields, known capabilities, and known auth modes. `ReadOnlyGuard` proves plans send no writes. Async tests call `asyncio.run(...)`; no additional HTTP or async test plugin is used. |
| Postgres integration | Tests run migrations and exercise transactional checkpoints, outbox writes, leases, tenant isolation, and RLS only when `ICUHUB_TEST_DATABASE_URL` is set. The separate application database URL uses a non-superuser, non-BYPASSRLS role for RLS proof. Tests skip with a clear reason when the database URL is unset. Kafka relay tests use a fake producer; a live Kafka smoke requires `ICUHUB_TEST_KAFKA`. |
| Live acceptance | The operator runs opt-in acceptance with `ICUHUB_ACC=1` in private infrastructure for every advertised kind, edition, profile, auth mode, and core capability. Results are returned and recorded per kind; offline success alone does not release a kind as `core` (FR-CNR-16, ADR-0020). |

## 7 Risks

The following condenses the top 15 risks raised in the persona review.

| # | Risk | Impact | Mitigation |
|---:|---|---|---|
| 1 | False correlation merges distinct issues or misses duplicates | Incorrect remediation ownership or duplicate tickets | Separate observations from cases; use versioned strong keys, canonical assets, confidence, near-miss goldens, audited split/merge, and measure both failure directions before automatic routing. |
| 2 | Retries duplicate Jira or Archer records, comments, scans, or builds | Repeated external side effects | Persist idempotency and natural keys before send, store remote IDs immediately, serialize within the partition, and fault-inject `outcome_unknown` reconciliation for every write class. |
| 3 | Partial or denied reads falsely close findings | Open risk disappears from the hub | Resolve only from explicit source close or complete snapshots, propagate scope completeness, fail closure on any page error, and apply the removal circuit breaker. |
| 4 | Tenant isolation fails in workers, caches, blobs, or correlation | Cross-tenant data or action exposure | Derive tenant from authenticated identity, use non-bypass RLS and `SET LOCAL`, tenant-scope all keys and storage, and test every foreground and background path adversarially. |
| 5 | SSRF or active scanning reaches unauthorized networks | Internal service access or unintended testing | Use origin allowlists, HTTPS, resolved-IP and port controls, redirect and DNS-rebinding defenses, default-deny egress, and target CIDR/domain checks at plan and apply. |
| 6 | Credentials or sensitive evidence leak | Account compromise or confidential-data exposure | Use `SecretRef`, write-only schemas, envelope encryption and production KEK, memory-only decrypted cache, redaction, bounded encrypted evidence, retention, and canary scans. |
| 7 | Malicious reports, HTML, archives, or webhook bodies exploit consumers | File disclosure, resource exhaustion, or stored active content | Verify before parse, use safe parsers, prohibit external entities, bound decompression/nesting/time/size, isolate temporary storage, quarantine failures, and render evidence inertly. |
| 8 | Webhook forgery or replay changes state or triggers actions | False observations or unauthorized operations | Use exact raw-byte per-vendor verification, constant-time comparison, timestamp windows where available, durable dedupe, rotation overlap, unknown-event rejection, and authoritative read-back. |
| 9 | Destructive or stale actions damage vendor state | Privilege, availability, or integrity loss | Default automation and destructive operations off, separate requester and approver, bind approval to the resolved plan hash, enforce current revisions and read-back, and make no generic rollback claim. |
| 10 | Bidirectional sync loops or wrong authority wins | Ping-pong updates and corrupted state | Use field ownership, versioned links, origin and remote-revision markers, echo suppression, and explicit conflicts; Jira-done never means scanner-fixed and Archer alone approves exceptions. |
| 11 | Edition, tier, or API drift silently reduces coverage | Advertised capability becomes incomplete without a clear signal | Use explicit kinds and profiles, feature/version/scope probes, edition fixtures, scheduled replay, `not_evaluated` health, and live matrices; block release on unresolved advertised behavior. |
| 12 | Async jobs, mutable pages, and rate limits lose or duplicate data | Incomplete inventory and findings or excess vendor load | Use durable async handles, overlap and stable IDs, typed cursors, export-expiry handling, shared limits, bounded retries, and crash/resume tests at each stage. |
| 13 | Audit evidence is incomplete or expires before review | Actions and source claims cannot be reconstructed | Store evidence manifests with digests, mapping versions, actors, approvals, plan/action IDs, and remote revisions; align retention with audit need and verify hash chain and export bundles. |
| 14 | OpenShift runtime or remediation gains excess privilege or leaks keys | Cluster-wide impact or private-key disclosure | Separate runtime and target identities, use least RBAC and restricted SCC, keep SCC writes off by default, redact diffs, check `resourceVersion`, and expose managed-audit blind spots. |
| 15 | Scope explosion yields nominal connectors without a trustworthy flow | Broad but unverifiable release claims | Fund vertical slices first, publish per-capability maturity, defer nonessential administration through explicit decisions, and tie every completion claim to global and vendor gates. |
